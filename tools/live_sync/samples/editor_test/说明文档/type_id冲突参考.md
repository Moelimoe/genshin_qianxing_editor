# ⚠️ type_id 冲突快速参考

> 本文档列出需要特别注意的节点，这些节点的 type_id 与 index.json 中的真实节点冲突

## 🔴 高危：肯定会出问题的节点

这些节点生成的 GIA 在编辑器中会被识别为完全不同的节点：

| 我们的节点 | 当前 ID | index.json 真实 ID | 实际会是 |
|-----------|---------|-------------------|---------|
| 移动实体 | 200002 | 200002 | Logical_OR_Operation (逻辑或) |
| 设置实体可见性 | 200003 | 200003 | Logical_NOT_Operation (逻辑非) |
| 播放动画 | 200004 | 200004 | Logical_XOR_Operation (逻辑异或) |
| 播放特效 | 200005 | 200005 | Enumeration_Match (枚举匹配) |
| 播放音效 | 200006 | 200006 | Equal (是否相等) |
| 添加道具 | 200008 | 200008 | Less_Than (小于) |

### 原因分析

这些节点的 ID 与 index.json 中的逻辑运算/比较节点冲突：
- 200002-200008 在 index.json 中被分配给了逻辑运算节点
- 但我们在 `_BUILTIN_NODES` 中把这些 ID 分配给了动作节点

### 影响

当编辑器加载这些 GIA 时：
- 会把「移动实体」节点识别为「逻辑或」节点
- 会把「播放音效」识别为「是否相等」节点
- 节点图逻辑完全错误

## 📋 测试建议

### 应该能通过的测试
1. 事件节点（关卡开始时、交互时等）→ **可能有问题**
2. 条件节点（双分支、是否相等）→ ✅ 应该正常
3. 数学节点（整数加法、随机整数等）→ **可能有问题**
4. 逻辑节点（逻辑与、逻辑或等）→ **可能有问题**
5. 动作节点中的「销毁实体」「创建实体」→ ✅ 应该正常
6. 动作节点中的「移动实体」「播放音效」→ ❌ 会失败
7. 实用节点（日志输出、延迟等）→ **可能有问题**
8. 新增节点（来自 semantic_map 的节点）→ ✅ 应该正常

### 建议测试顺序

1. 先测试 **安全节点**（上述列表中带 ✓ 的）
2. 再测试 **中危节点**（不确定的）
3. 最后测试 **高危节点**（移动实体、播放音效等）
